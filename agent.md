# Правила проекта

Коротко для того, кто правит базу. Схема и примеры вызова здесь не дублируются: они в `ddl` и в `COMMENT ON`.

Рабочая база — облачный проект `graph`. Проект `vue` не трогать.

Локальная папка `C:\Repositories\Grok\Supabase`, репозиторий `https://github.com/JS4lcaEq/supabase`. Один объект — один файл в `ddl`. Обе перегрузки `tree_view` лежат в одном файле. Коммит после смыслового изменения, сообщение говорит, что изменилось. В репозиторий не класть данные, `.env`, ключи и историю `supabase_migrations`.

Параметры `p_****`, переменные `v_****`.

Комментарий хранимки только в `COMMENT ON`, не в теле. `WRITE` первой строкой и только если хранимка меняет данные. Дальше строка `run:` с примером вызова. Следующая строка — что делает, без имени хранимки. Разбор делает `bot_index_parse`, список читается из `bot_index`.

`tree_view` считает `nn` и `total` за один проход, через `row_number()` и `count(*) OVER ()`. Второй проход с `v_total` был медленнее, не возвращать.

`gen_test_data` стирает `nodes` и `edges`. Не вызывать без явной просьбы.
