# Управление графом

Postgres-схема в Supabase: дерево узлов и рёбер, выборка страницы дерева и индекс комментариев хранимок.

Данных и ключей в репозитории нет. Файлы в `ddl` можно прогнать на пустой базе.

## Объекты

`nodes` — узел: `id`, `nm`.
`edges` — ребро родителя к ребёнку: `pid`, `cid`. Оба ссылаются на `nodes` и удаляются вместе с узлом.

`gen_test_data(p_deep, p_length)` — заменяет текущие данные деревом. На первом уровне `p_length` корней, дальше у каждого родителя ровно `p_length` детей, глубина `p_deep`. Имена вида `Node_000001`.

`tree_view(p_root_id, p_from, p_to)` — страница дерева в порядке `path`. `p_root_id` пустой значит все корни. `nn` — номер строки по всему дереву, `total` — сколько узлов в этом дереве.

`tree_view(p_root_id, p_mask, p_from, p_to)` — то же, но только пути к узлам, в имени которых есть маска.

`tree_view_perf_compare()` — сравнивает два способа посчитать `total` на странице 50–100. Данные не меняет.

`bot_index` — список хранимок: схема, имя, вид, аргументы, признак записи, пример вызова и назначение.
`bot_index_parse` — разбирает текст комментария на эти три поля.

## Комментарии

Назначение хранимки живёт только в `COMMENT ON`, не в теле.

Первая строка `WRITE` большими буквами, и только если хранимка меняет данные.
Дальше строка `run:` с примером вызова.
Следующая строка без тега — что делает хранимка, без её имени.

Параметры в коде — `p_****`, переменные — `v_****`.

## Папка

```
ddl/tables/     nodes, edges
ddl/views/      bot_index
ddl/routines/   хранимки и их COMMENT ON
```

Один объект — один файл. Обе перегрузки `tree_view` лежат вместе. `bot_index` — view, отдельный файл у неё есть.
