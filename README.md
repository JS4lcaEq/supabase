# Управление графом

Postgres-схема в Supabase: дерево узлов и рёбер, выборка страницы дерева и индекс комментариев хранимок.

Данных и ключей в репозитории нет. Файлы в `ddl` можно прогнать на пустой базе.

## Объекты

`nodes` — узел: `id`, `nm`.
`edges` — ребро родителя к ребёнку: `pid` (Parent Id), `cid` (Child Id). Оба ссылаются на `nodes` и каскадно удаляются вместе с узлом.

`gen_test_data(p_deep, p_length)` — по-прежнему стирает граф и заменяет текущие данные деревом. На первом уровне `p_length` корней, дальше у каждого родителя ровно `p_length` детей, глубина `p_deep`. Имена вида `Node_000001`.

`tree_view(p_root_id, p_from, p_to)` — страница дерева в порядке `path`. `p_root_id` пустой значит все корни. `nn` — номер строки по всему дереву, `total` — сколько узлов в этом дереве.

`tree_view(p_root_id, p_mask, p_from, p_to)` — то же, но только пути к узлам, в имени которых есть маска.

`tree_view_perf_compare()` — сравнивает два способа посчитать `total` на странице 50–100. Данные не меняет.

`bot_index` — список хранимок: схема, имя, вид, аргументы, признак записи, пример вызова и назначение.
`bot_index_parse` — разбирает текст комментария на эти три поля.

## Хранимки

У `anon` есть `EXECUTE`. Для `gen_test_data(p_deep, p_length)` в `ddl` нет `GRANT`.

`node_list(p_pid)` — прямые дети узла по `pid`; если `pid` равен null, корни.
`node_get(p_id)` — один узел по `id`.
`node_save(p_id, p_nm)` — вставляет узел, если `id` равен null, иначе меняет имя. WRITE
`node_delete(p_id)` — удаляет узел по `id`; рёбра уходят каскадом, дети остаются. WRITE
`node_find(p_mask)` — узлы, в имени которых есть образец; не больше 50, по `id`.
`node_all()` — узлы по `id`, не больше 100000.

`edge_list(p_pid)` — прямые рёбра узла по `pid`.
`edge_get(p_pid, p_cid)` — одно ребро по `pid` и `cid`.
`edge_add(p_pid, p_cid)` — добавляет ребро pid-cid; повтор и null запрещены. WRITE
`edge_delete(p_pid, p_cid)` — удаляет ребро по `pid` и `cid`; узлы не трогает. WRITE
`edge_delete_end(p_id)` — удаляет рёбра, где узел стоит как `pid` или `cid`. WRITE
`edge_all()` — рёбра по `pid` и `cid`, не больше 100000.

`db_ping()` — текущее время базы в секундах, тип `integer`: unix-секунды, без сдвига часового пояса.

`gen_test_data(p_deep, p_length)` — строит дерево узлов и рёбер и заменяет текущие данные; по-прежнему стирает граф. WRITE
`gen_test_data(p_deep, p_length, p_start)` — Чистит КАСКАДНО ВСЕХ потомков узла p_start и строит от него новое поддерево тестовых данных; старые данные ближе к корню от этого узла не трогает. WRITE

## Комментарии

Назначение хранимки живёт только в `COMMENT ON`, не в теле.

Первая строка `WRITE` большими буквами, и только если хранимка меняет данные.
Дальше строка `run:` с примером вызова.
Следующая строка без тега — что делает хранимка, без её имени.

Параметры в коде — `p_****`, переменные — `v_****`.

## Папка

```
ddl/tables/     nodes, edges
ddl/views/      bot_index
ddl/routines/   хранимки и их COMMENT ON
```

Один объект — один файл. Обе перегрузки `tree_view` лежат вместе. `bot_index` — view, отдельный файл у неё есть.
